The resolved presentation design uses a serializable CDI `@Named @ViewScoped` editor bean. It loads `CargoRoute` only through `BookingServiceFacade`, converts the DTO's `MM/dd/yyyy` date representation with a per-load `SimpleDateFormat`, and submits a `java.util.Date` through the facade. Do not introduce a shared mutable formatter, access domain objects directly, or silently turn malformed input into null.

The resolved validation rule is only that a selected date is non-null. Do not invent a minimum date, future-only rule, ordering against the previous deadline, or itinerary chronology rule. A failed facade update must not be presented as success or close the dialog.

## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDate.java`

Use this shape:

```java
@Named
@ViewScoped
public class ChangeArrivalDeadlineDate implements Serializable {
    private static final long serialVersionUID = 1L;

    private String trackingId;
    private CargoRoute cargo;
    private Date arrivalDeadlineDate;

    @Inject
    private BookingServiceFacade bookingServiceFacade;
}
```

Provide `getTrackingId()`, `setTrackingId(String)`, `getCargo()`, `getArrivalDeadlineDate()`, `setArrivalDeadlineDate(Date)`, `load()`, and `changeArrivalDeadline()`.

`load()` must:

1. Call `bookingServiceFacade.loadCargoForRouting(trackingId)`.
2. Retain the returned `CargoRoute`.
3. Parse the DTO's displayed `MM/dd/yyyy` deadline using a newly created `SimpleDateFormat("MM/dd/yyyy")` for this load.
4. Store the parsed value in `arrivalDeadlineDate`.
5. Surface malformed DTO data as a clear application/view failure consistent with repository conventions; do not swallow it, print only a stack trace, or submit null.

`changeArrivalDeadline()` must:

1. Reject a null selected date through normal JSF validation or explicit bean validation.
2. Call `bookingServiceFacade.changeDeadline(trackingId, arrivalDeadlineDate)`.
3. Only after successful delegation, call `PrimeFaces.current().dialog().closeDynamic("DONE")`.
4. Leave the dialog open and surface the failure if delegation fails.

If practical, add a container-free JUnit test using a hand-written fake facade. Prove the correct tracking ID is loaded, the date-only DTO value becomes the editable date, selected tracking ID/date are delegated, malformed input is surfaced, and null submission is rejected.

## Completion gates

- `./mvnw clean package -Popenliberty` succeeds on JDK 17.
- The bean is serializable and uses the established CDI/JSF annotations.
- Imports and fields show that the bean depends only on the facade and facade DTOs, never domain model or repository classes.
- Date parsing uses a per-load formatter and failures cannot become a null/success-shaped result.
- Submission closes with `"DONE"` only after successful facade delegation.
- Any focused test is container-free and introduces no mocking dependency.

## Out of scope

- Dialog launcher, XHTML, Administration table, navigation, or inline editing.
- Direct domain/repository access or changes to the facade/service contracts.
- Shared `SimpleDateFormat`, new DTO date fields, new date libraries, or dependency additions.
- New chronological business rules.
- Swallowing parse, validation, lookup, or facade failures.
